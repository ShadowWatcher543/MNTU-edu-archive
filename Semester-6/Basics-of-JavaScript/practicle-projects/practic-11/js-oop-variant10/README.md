## Реалізована архітектура класів та принципів ООП

Проект демонструє побудову ієрархічної структури даних зоомагазину з використанням стандартів ES6+ класів та TypeScript:

### 1. Ієрархія сутностей (Наслідування та Поліморфізм)
* **`Pet`** — базовий клас тварини. Містить **інкапсульовані приватні поля (`#id`, `#name`, `#price` тощо)** для захисту внутрішнього стану об'єкта від прямого несанкціонованого втручання. Доступ до них реалізовано виключно через публічні геттери та сеттери.
* **`Dog` / `Cat` / `Bird`** — класи-спадкоємці, які використовують ключові слова `extends` та метод `super()` для розширення базових властивостей специфічними параметрами (порода, забарвлення, вміння говорити тощо).
* **Поліморфізм** реалізовано через перевизначення методу `getDetails()`, який гнучко комбінує базові дані тварини зі специфічними параметрами кожної конкретної підгрупи під час рендерингу.

### 2. Логічний центр (`PetStore`)
* Обліковує поточний інвентар та зберігає історію комерційних операцій у приватному полі `#salesHistory`.
* Реалізує внутрішній **приватний метод `#calculateFinalPrice`** для прихованого прорахунку додаткової вартості (податку магазину 5%) під час продажу.
* Містить **статичний метод `PetStore.formatCurrency`**, який виконує роль глобальної утиліти для гарного форматування грошових сум.

### 3. Персистентність даних (Збереження стану)
* Реалізовано повну синхронізацію інвентарю та журналу продажів із **`localStorage`**. Будь-які зміни (додавання тварин, вакцинація, покупка) автоматично записуються в браузер і зберігаються після перезавантаження сторінки (F5).
* Для зручності тестування додано **функціонал примусового скидання сховища**. За допомогою спеціальної кнопки інтерфейсу користувач може повністю стерти збережений стан і миттєво повернути магазин до початкового дефолтного каталогу тварин.

## Алгоритмічні особливості

* Всі внутрішні операції пошуку об'єктів за ID, фільтрації каталогу за віком чи видом, а також зсуву інвентарю під час продажу реалізовано вручну через **класичні цикли `for`** без застосування високорівневих методів масивів на кшталт `.filter()`, `.find()` або `.splice()`.
* Обробку дій користувача (кліки на кнопки «Купити», «Вакцинувати» та «Скинути сховище») організовано за принципом **делегування подій** через один спільний глобальний слухач кліків.
